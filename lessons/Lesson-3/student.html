1. Что такое tsconfig.json

1. What tsconfig.json is

tsconfig.json — это конфигурационный файл TS-проекта. Лежит в корне проекта. Говорит компилятору: что компилировать, в какую версию JS, насколько строго проверять, куда складывать результат.

tsconfig.json is the TS project's config file. Sits at the project root. Tells the compiler: what to compile, which JS version to target, how strictly to check, where to put the output.

Главное: поведение TypeScript на 80% определяется файлом tsconfig.json. Без правильно настроенного конфига TS почти бесполезен.

Key insight: TypeScript behavior is 80% determined by tsconfig.json. Without a proper config TS is nearly useless.

4. Что включает "strict": true

4. What "strict": true turns on

  • noImplicitAny — параметры без типа запрещены
  • strictNullChecks — null и undefined — отдельные типы
  • strictFunctionTypes — проверка совместимости параметров функций
  • strictBindCallApply — проверка аргументов .bind/.call/.apply
  • strictPropertyInitialization — поля класса инициализированы в конструкторе
  • noImplicitThis — запрещён this с неявным типом
  • useUnknownInCatchVariables — catch (e) → e: unknown
  • alwaysStrict — добавляет "use strict" в выход
  • noImplicitAny — untyped parameters forbidden

5. Финальный tsconfig.json для курса

5. Final tsconfig.json for the course

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",

    "rootDir": "./src",
    "outDir": "./dist",

    "strict": true,
    "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true,
    "noImplicitOverride": true,
    "exactOptionalPropertyTypes": true,

    "sourceMap": true,
    "declaration": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}

Не забыть: для ESM в Node.js в package.json добавить "type": "module".

Don't forget: for ESM in Node.js add "type": "module" to package.json.

7. Workflow: 4 команды

7. Workflow: 4 commands

КомандаЧто делаетКогда
CommandWhatWhen

npx tsc --noEmitТолько проверить типыCI, pre-commit, во время разработки

Запомни: tsx запускает, но не делает строгой проверки. Для проверки нужен отдельный tsc --noEmit. Профи держат оба в работе.

Remember: tsx runs but doesn't do a strict type-check. Use a separate tsc --noEmit for checking. Pros run both.

10. Source maps

10. Source maps

Source map (.js.map) — файл, который связывает строки в скомпилированном .js со строками в исходном .ts. Включается опцией "sourceMap": true.

Source map (.js.map) — file that links lines in compiled .js to lines in source .ts. Enabled via "sourceMap": true.
