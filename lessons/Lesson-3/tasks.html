Задание 4. Поймать 4 ошибки strict-режима
Task 4. Catch 4 strict-mode errors
Средне Medium 20 мин
Увидеть на живом коде, как именно strict-режим ловит баги, которые в JS остались бы незамеченными до прода. See on real code how strict mode catches bugs that in JS would slip through to production.

Шаги:

Steps:

  1. Создайте файл src/demo.ts с этим «плохим» кодом: 
    // 1. Параметр без типа
function greet(name) {
    return "Hello, " + name.toUpperCase();
}

// 2. Map.get() может вернуть undefined
function findUser(id: number) {
    const users = new Map<number, string>();
    return users.get(id);
}
const user = findUser(42);
console.log(user.length);

// 3. Индекс за пределами массива
const items = ["apple", "banana"];
const tenth = items[10];
console.log(tenth.length);

// 4. catch без типа
try {
    JSON.parse("{");
} catch (e) {
    console.log(e.message);
}
  2. Запустите npm run check. Запишите в тетрадь все ошибки, которые показал компилятор (должно быть 4).
  3. Для каждой ошибки запишите: что именно поломалось бы в продакшене, если бы strict был выключен.
  1. Create src/demo.ts with this "bad" code: 
    // 1. Parameter without type
function greet(name) {
    return "Hello, " + name.toUpperCase();
}

// 2. Map.get() may return undefined
function findUser(id: number) {
    const users = new Map<number, string>();
    return users.get(id);
}
const user = findUser(42);
console.log(user.length);

// 3. Index out of bounds
const items = ["apple", "banana"];
const tenth = items[10];
console.log(tenth.length);

// 4. catch without type
try {
    JSON.parse("{");
} catch (e) {
    console.log(e.message);
}
  2. Run npm run check. Write down in your notebook every error the compiler shows (should be 4).
  3. For each error note: what specifically would break in production if strict were off.
  • В тетради записаны все 4 текста ошибок от компилятора
  • По каждой ошибке — пояснение, какой рантайм-баг был бы в JS
  • Сделан вывод: strict-режим заранее ловит то, что в JS падает только в проде
  • All 4 compiler error texts written down
  • For each — an explanation of which runtime bug would happen in JS
  • Conclusion: strict mode catches in advance what crashes in production with JS

Подсказка по ошибке #3: индекс [10] в массиве из 2 элементов даёт undefined в рантайме. Без флага noUncheckedIndexedAccess TS думает, что это string, и не предупреждает.

Hint for error #3: index [10] on a 2-element array returns undefined at runtime. Without noUncheckedIndexedAccess TS thinks it's string and stays silent.
