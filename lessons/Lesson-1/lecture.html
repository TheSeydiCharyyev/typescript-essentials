1. Сначала немного о JavaScript

1. First, a bit about JavaScript

Чтобы понять TypeScript, нужно сначала понять JavaScript — ведь TypeScript существует именно из-за него.

To understand TypeScript, you first need to understand JavaScript — because TypeScript exists precisely because of it.

JavaScript (JS) — это язык программирования, который изначально придумали в 1995 году, чтобы «оживить» веб-страницы: проверять формы, показывать всплывающие окна, реагировать на клики. Сегодня JavaScript работает почти везде: в браузере, на сервере (через Node.js), в мобильных и десктопных приложениях.

JavaScript (JS) is a programming language created in 1995 to make web pages "alive": validate forms, show popups, react to clicks. Today JavaScript runs almost everywhere: in browsers, on servers (via Node.js), in mobile and desktop apps.

JavaScript — самый популярный язык программирования в мире. 12+ лет подряд он занимает первое место в опросах разработчиков. Но у него есть один большой недостаток, о котором — в следующем разделе.

JavaScript is the most popular programming language in the world. For 12+ years in a row it has held first place in developer surveys. But it has one big flaw, which we'll discuss in the next section.

Несмотря на похожее название, JavaScript и Java — это совершенно разные языки. Имя «JavaScript» — это маркетинговое решение 1995 года, чтобы «прокатиться» на популярности Java. Как говорят разработчики: «Java относится к JavaScript так же, как автомобиль (car) к ковру (carpet)».

Despite the similar name, JavaScript and Java are completely different languages. The name "JavaScript" was a 1995 marketing move to ride on Java's popularity. As developers say: "Java is to JavaScript what a car is to a carpet."

2. Проблема, которую решает TypeScript

2. The problem TypeScript solves

JavaScript — динамически-типизированный язык. Это значит, что переменная может в любой момент сменить тип:

JavaScript is a dynamically-typed language. This means a variable can change its type at any time:

// JavaScript — никаких ограничений
let age = 18;          // число
age = "восемнадцать";  // теперь строка — JS не возражает
age = [1, 8];          // теперь массив — тоже OK
age = { years: 18 };   // теперь объект — никаких ошибок

На первый взгляд это удобно — мы свободны делать что угодно. Но на практике эта «свобода» приводит к ошибкам, которые очень сложно ловить:

At first glance this is convenient — we're free to do anything. But in practice this "freedom" leads to bugs that are very hard to catch:

Реальный пример из жизни:

Real-life example:

function calculatePrice(price, quantity) {
    return price * quantity;
}

// Передаём ПО ОШИБКЕ строку вместо числа:
calculatePrice("100", 3);   // → "100100100" ← БАГ! Получили строку
calculatePrice(100, "3");   // → "1003" ← Снова баг
calculatePrice(100, 3);     // → 300 ← правильно

JS не сообщит об ошибке. Программа запустится, выведет странный результат, и баг обнаружится только в проде, когда покупатель увидит цену "100100100" рублей. TypeScript бы сразу это поймал — ещё в редакторе кода, до запуска.

JS won't report an error. The program runs, outputs a weird result, and the bug only surfaces in production when a customer sees a price of "100100100". TypeScript would catch this instantly — right in the editor, before the program even runs.

Чем больше проект, тем сильнее болит. В крупных приложениях — десятки тысяч строк кода, сотни функций, и ни одна из них не «знает», какие данные ей передадут. В компании Microsoft в 2010 году с этой болью столкнулись напрямую: они писали Visual Studio Online (огромный веб-редактор кода) и понимали, что без типизации поддерживать такой проект невозможно. Так и появился TypeScript.

The bigger the project, the more it hurts. Big apps have tens of thousands of lines and hundreds of functions, none of which "know" what data they'll receive. Microsoft hit this pain directly in 2010: they were building Visual Studio Online (a huge web-based code editor) and realized that maintaining such a project without typing was impossible. That's how TypeScript was born.

3. История TypeScript

3. A brief history of TypeScript

2010 — Внутренняя разработка в Microsoft
2010 — Internal development at Microsoft

Команда Microsoft, работавшая над Visual Studio Online, решила, что писать большой проект на чистом JavaScript слишком трудно. Создатель C# и Delphi Андерс Хейлсберг (Anders Hejlsberg) возглавил разработку нового языка, который должен был добавить статическую типизацию к JS, не ломая совместимость.

A Microsoft team building Visual Studio Online realized that writing a large project in plain JavaScript was too hard. The creator of C# and Delphi, Anders Hejlsberg, led the design of a new language that would add static typing to JS without breaking compatibility.

Октябрь 2012 — TypeScript 0.8: первый публичный релиз
October 2012 — TypeScript 0.8: first public release

Microsoft выложила TypeScript на GitHub под открытой лицензией Apache 2.0. Реакция сообщества была неоднозначной: многие разработчики JS не хотели «писать на C# в браузере». Но проект быстро начал набирать сторонников.

Microsoft released TypeScript on GitHub under the open Apache 2.0 license. Community reactions were mixed — many JS devs didn't want "to write C# in the browser". But the project quickly gained supporters.

2014 — TypeScript 1.0
2014 — TypeScript 1.0

Первая стабильная версия. Язык получил классы, модули, generics — все основные возможности, которые есть и сегодня.

The first stable version. The language got classes, modules, and generics — all the core features it still has today.

2016 — Angular 2 переходит на TypeScript
2016 — Angular 2 switches to TypeScript

Команда Google Angular (один из самых популярных фреймворков) объявила, что Angular 2 будет полностью написан на TypeScript. Это стало переломным моментом: TS перестал быть «экспериментом Microsoft» и превратился в стандарт индустрии.

The Google Angular team (one of the most popular frameworks) announced that Angular 2 would be fully written in TypeScript. This was a turning point — TS stopped being "a Microsoft experiment" and became an industry standard.

2018-2020 — Эра массового перехода
2018-2020 — The era of mass adoption

React, Vue, Node.js-проекты — все массово переходят на TypeScript. Slack, Airbnb, Netflix, Lyft публично рассказывают о миграции своих кодовых баз с JS на TS. Появляется фраза: «Если бы я начинал проект сегодня — обязательно бы выбрал TypeScript».

React, Vue, Node.js projects — everyone migrates to TypeScript. Slack, Airbnb, Netflix, Lyft publicly share their migrations from JS to TS. A common phrase emerges: "If I were starting a project today, I'd definitely pick TypeScript."

2024 — TypeScript 5.x
2024 — TypeScript 5.x

Современная пятая версия. Согласно опросу State of JS 2024, более 80% профессиональных JS-разработчиков используют TypeScript ежедневно. По данным GitHub Octoverse, TS обогнал Java и стал третьим по популярности языком на GitHub.

The modern fifth major version. According to State of JS 2024, over 80% of professional JS developers use TypeScript daily. According to GitHub Octoverse, TS has surpassed Java to become the third most popular language on GitHub.

Сегодня (2026)
Today (2026)

TypeScript — фактический стандарт для серьёзной веб-разработки. На нём пишут фронтенды (React, Next.js, Vue, Angular, Svelte), серверы (NestJS, Deno, Bun), мобильные приложения (React Native, Expo), даже сам VS Code и движок Deno написаны на TypeScript.

TypeScript is the de facto standard for serious web development. It powers frontends (React, Next.js, Vue, Angular, Svelte), servers (NestJS, Deno, Bun), mobile apps (React Native, Expo). Even VS Code itself and the Deno runtime are written in TypeScript.

If Brendan Eich created JavaScript "on his knee" in 10 days, Hejlsberg is the opposite: he brought 30+ years of designing large industrial languages to the JS world. That's why TypeScript feels like "JavaScript designed by grown-up engineers for serious systems".

5. Что такое TypeScript

5. What is TypeScript

TypeScript (TS) — это строго-типизированная надстройка (superset) над JavaScript, разработанная Microsoft. Любой валидный JS-код является валидным TS-кодом. TypeScript добавляет к JavaScript систему типов, проверку на этапе разработки и более понятные подсказки в редакторе. В браузере и Node.js TypeScript не запускается напрямую — он компилируется в обычный JavaScript.

TypeScript (TS) is a strongly-typed superset of JavaScript developed by Microsoft. Any valid JS code is also valid TS code. TypeScript adds a type system, design-time checks, and richer editor hints. Browsers and Node.js don't run TypeScript directly — it gets compiled down to plain JavaScript.

Разберём ключевые слова из определения.

Let's unpack the key terms.

5.1. «Строго-типизированный»

5.1. "Strongly-typed"

Каждое значение в TypeScript имеет тип, и тип проверяется заранее, ещё до запуска. Если вы попытаетесь сделать что-то некорректное — например, прибавить число к массиву — TypeScript сразу подчеркнёт ошибку красным в редакторе кода. Программа просто не скомпилируется, пока вы не исправите проблему.

Every value in TypeScript has a type, and the type is checked in advance, before the code runs. If you try to do something incorrect — say, add a number to an array — TypeScript highlights the error in red right in your editor. The program simply won't compile until you fix the issue.

5.2. «Надстройка» (superset) над JavaScript

5.2. "Superset" of JavaScript

Это, пожалуй, самое важное в определении. Любой JavaScript-файл — это уже валидный TypeScript-файл. Достаточно просто переименовать app.js в app.ts — и код будет работать. TypeScript не отменяет JavaScript, он его расширяет: всё, что есть в JS, есть и в TS, плюс типы и несколько дополнительных возможностей.

This is probably the most important part of the definition. Any JavaScript file is already a valid TypeScript file. You can rename app.js to app.ts and the code will work. TypeScript doesn't replace JavaScript — it extends it: everything in JS is in TS, plus types and a few extra features.

5.3. «Компилируется в JavaScript»

5.3. "Compiles to JavaScript"

Браузер не понимает TypeScript. Node.js (без специальных инструментов) — тоже. Поэтому каждый .ts-файл проходит через компилятор по имени tsc (TypeScript Compiler), который превращает его в обычный .js-файл. Этот процесс называется компиляция или транспиляция (transpile = transform + compile).

Browsers don't understand TypeScript. Neither does Node.js (without extra tools). So each .ts file goes through a compiler called tsc (TypeScript Compiler), which turns it into a regular .js file. This process is called compilation or transpilation (transpile = transform + compile).

5.4. «Разработан Microsoft»

5.4. "Developed by Microsoft"

TypeScript — open-source проект (Apache 2.0) на GitHub: github.com/microsoft/TypeScript. Любой может предложить улучшение или сообщить о баге. Microsoft не «владеет» языком в смысле платных лицензий — он бесплатный для всех, в любых проектах, навсегда.

TypeScript is an open-source project (Apache 2.0) on GitHub: github.com/microsoft/TypeScript. Anyone can suggest improvements or report bugs. Microsoft doesn't "own" the language in the sense of paid licenses — it's free for everyone, in any project, forever.

6. «Надстройка над JS» — что это значит на практике

6. "A superset of JS" — what that means in practice

┌──────────────────────────────┐ │ TypeScript │ │ ┌───────────────────────┐ │ │ │ JavaScript │ │ │ │ let, const, if, │ │ │ │ function, class, │ │ │ │ Array, Promise... │ │ │ └───────────────────────┘ │ │ + типы (number, string) │ │ + interface, type, generic │ │ + enum, readonly, private │ └──────────────────────────────┘

Возьмите любой JavaScript-файл — и переименуйте в .ts. Поздравляю, вы написали TypeScript:

Take any JavaScript file and rename it to .ts. Congratulations — you've written TypeScript:

// hello.ts — это и валидный JS, и валидный TS
console.log("Hello!");

const numbers = [1, 2, 3];
const sum = numbers.reduce((a, b) => a + b, 0);
console.log(sum);  // 6

А теперь добавим типы, и код станет «настоящим TypeScript»:

Now let's add types, and the code becomes "real TypeScript":

// hello.ts с типами
const numbers: number[] = [1, 2, 3];

function sum(arr: number[]): number {
    return arr.reduce((a, b) => a + b, 0);
}

console.log(sum(numbers));  // 6
console.log(sum("hello"));  // ❌ Ошибка ещё в редакторе!

Главный приём TypeScript: вы постепенно добавляете типы туда, где это полезно, и оставляете «как есть» там, где это не нужно. Не надо переписывать всё разом — TS позволяет мигрировать файл за файлом.

The key TypeScript trick: you gradually add types where useful and leave the rest "as is". You don't need to rewrite everything at once — TS lets you migrate file by file.

7. Как работает TypeScript: компиляция

7. How TypeScript works: compilation

Браузер и Node.js понимают только JavaScript. Поэтому жизненный цикл TS-файла выглядит так:

Browsers and Node.js only understand JavaScript. So the TS file life cycle looks like this:

┌─────────────┐ tsc ┌─────────────┐ запуск ┌──────────────┐ │ app.ts │ ───────────▶ │ app.js │ ──────────▶ │ Браузер / │ │ (с типами) │ компилятор │ (чистый JS) │ │ Node.js │ └─────────────┘ └─────────────┘ └──────────────┘ ваш исходник готовый код запуск
1

Вы пишете app.ts с аннотациями типов.

You write app.ts with type annotations.

2

Запускаете компилятор: в терминале команду tsc app.ts.

Run the compiler: the terminal command tsc app.ts.

3

Компилятор делает две вещи: а) проверяет типы (если есть ошибки — сообщает); б) генерирует обычный app.js без типов.

The compiler does two things: a) checks types (reports errors if any); b) generates a plain app.js without types.

4

Полученный app.js запускается в браузере (через <script>) или в Node.js (через node app.js).

The resulting app.js runs in the browser (via <script>) or in Node.js (via node app.js).

Важно понять: типы из TypeScript не попадают в скомпилированный JS-файл. Они существуют только во время разработки — для проверки кода и подсказок в редакторе. Когда ваш код наконец-то «доедет» до браузера, он будет на чистом JavaScript, и браузер не увидит ни одной строчки : number или interface.

Important to understand: TypeScript types do not appear in the compiled JS file. They exist only at development time — to check code and provide editor hints. By the time your code reaches the browser, it's plain JavaScript with no : number or interface in sight.

Пример «до и после»

Before-and-after example

Что вы пишете (app.ts)
What you write (app.ts)
function greet(name: string): string {
    return "Hello, " + name;
}

const message: string = greet("Seydi");
console.log(message);
Что получает браузер (app.js)
What the browser gets (app.js)
function greet(name) {
    return "Hello, " + name;
}

const message = greet("Seydi");
console.log(message);

Видите? Аннотации : string просто исчезли. Они «выполнили свою работу» в момент компиляции — проверили, что вы передали в функцию строку, а не число, — и больше не нужны.

See? The : string annotations simply vanished. They "did their job" at compile time — verifying that you passed a string, not a number — and aren't needed anymore.

Function types

Try it yourself in your browser: visit typescriptlang.org/play — the official TypeScript online playground. Paste any example above and change a type to a "wrong" one (e.g., put string where number is expected). You'll see the editor underline the error.

Когда выбирать что: для маленьких скриптов на 50 строк — JavaScript. Для всего остального — TypeScript. Особенно если в проекте больше одного человека или вы планируете поддерживать его дольше месяца.

When to choose what: for tiny 50-line scripts — JavaScript. For anything else — TypeScript. Especially if more than one person works on the project or you plan to maintain it for more than a month.

10. Where TypeScript is used

11. What you need to start working with TypeScript
