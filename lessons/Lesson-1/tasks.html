Занятие 1: Что такое TypeScript — 6 заданий от простого к сложному

Lesson 1: What is TypeScript — 6 tasks from easy to advanced

Важно: для всех заданий не нужно ничего устанавливать на компьютер. Вся практика идёт в онлайн-песочнице typescriptlang.org/play и в браузере. Установку инструментов разберём в занятии 2.

Important: for all these tasks you don't need to install anything on your computer. All the practice happens in the online playground at typescriptlang.org/play and in the browser. Tool installation comes in Lesson 2.

Задание 1. Знакомство с TypeScript Playground
Task 1. Meet the TypeScript Playground
Легко Easy 10 мин
Открыть онлайн-песочницу TypeScript, увидеть две панели (код и результат компиляции в JS), понять, как работает компилятор. Open the TypeScript online playground, see the two panels (code and compiled JS result), and understand how the compiler works.

Шаги:

Steps:

  1. Откройте в браузере typescriptlang.org/play.
  2. Слева — поле для кода TS, справа — то, во что он скомпилируется (JS).
  3. Удалите весь код слева и вставьте: 
    let age: number = 18;
let name: string = "Seydi";
console.log(name + " is " + age);
  4. Посмотрите справа: что появилось? Куда пропали : number и : string?
  5. Нажмите кнопку «Run» в правом верхнем углу — внизу под кодом откроется консоль с результатом.
  1. Open typescriptlang.org/play in your browser.
  2. On the left — TS code editor, on the right — what it compiles to (JS).
  3. Delete all the code on the left and paste: 
    let age: number = 18;
let name: string = "Seydi";
console.log(name + " is " + age);
  4. Look on the right: what appeared? Where did : number and : string go?
  5. Press the "Run" button in the top right — a console with the result opens below the code.
  • Песочница открыта, видны обе панели — TS и JS
  • В консоли видна строка Seydi is 18
  • В тетрадь записано: чем JS-код справа отличается от TS-кода слева
  • The playground is open, both panels (TS and JS) are visible
  • The console shows Seydi is 18
  • Written in the notebook: how the JS code on the right differs from the TS code on the left

Если правой панели не видно — нажмите «.JS» на верхней панели, чтобы её включить.

If you don't see the right panel — click ".JS" on the top toolbar to enable it.

Задание 2. Поймать ошибку до запуска
Task 2. Catch an error before runtime
Легко Easy 10 мин
Увидеть своими глазами главную силу TypeScript — обнаружение ошибок типов прямо в редакторе. See firsthand the main strength of TypeScript — catching type errors right in the editor.

Шаги:

Steps:

  1. В песочнице вставьте этот «правильный» код и убедитесь, что ошибок нет: 
    let age: number = 18;
age = 19;
console.log(age);
  2. Теперь намеренно сломайте: замените age = 19 на age = "девятнадцать".
  3. Посмотрите, что подчеркнёт TypeScript красным. Наведите курсор на красную «волну» — появится подсказка с описанием ошибки.
  4. Запишите в тетрадь полный текст ошибки.
  5. Попробуйте ещё 2 «поломки»: age = true и age = [1, 2]. Запишите ошибки от каждой.
  1. In the playground, paste this "correct" code and verify there are no errors: 
    let age: number = 18;
age = 19;
console.log(age);
  2. Now break it intentionally: replace age = 19 with age = "nineteen".
  3. See what TypeScript underlines in red. Hover over the red "wave" — a tooltip with the error description appears.
  4. Write down the full error text in your notebook.
  5. Try 2 more breaks: age = true and age = [1, 2]. Write down each error.
  • Записаны тексты трёх разных ошибок типизации
  • Понятно: ошибки появились до нажатия «Run» — TypeScript нашёл их сам, читая код
  • Written down the text of three different type errors
  • You understand: errors appeared before pressing "Run" — TypeScript found them by just reading the code

Все три ошибки начинаются со слов Type '...' is not assignable to type 'number'. Это и есть главное сообщение TypeScript: «вы хотите положить не то, что объявили».

All three errors start with Type '...' is not assignable to type 'number'. That's TypeScript's main message: "you're trying to assign something different from what you declared".

Part A — JavaScript (we run the bug):

  2. Вставьте в консоль и нажмите Enter: 
    function calculatePrice(price, quantity) {
    return price * quantity;
}
console.log(calculatePrice("100", 3));
console.log(calculatePrice(100, "3"));
console.log(calculatePrice(100, 3));
  3. Запишите все три результата.
  1. Open any site, press F12 → Console tab.
  2. Paste in the console and press Enter: 
    function calculatePrice(price, quantity) {
    return price * quantity;
}
console.log(calculatePrice("100", 3));
console.log(calculatePrice(100, "3"));
console.log(calculatePrice(100, 3));
  3. Write down all three results.

Часть Б — TypeScript (TS не даёт повторить баг):

Part B — TypeScript (TS won't let the bug happen):

  1. Откройте typescriptlang.org/play и вставьте: 
    function calculatePrice(price: number, quantity: number): number {
    return price * quantity;
}
console.log(calculatePrice("100", 3));
console.log(calculatePrice(100, "3"));
console.log(calculatePrice(100, 3));
  2. Посмотрите, какие строки TypeScript подчеркнул красным. Запишите тексты ошибок.
  3. Уберите «битые» вызовы (со строками), оставьте только calculatePrice(100, 3). Нажмите Run и убедитесь, что выведется 300.
  1. Open typescriptlang.org/play and paste: 
    function calculatePrice(price: number, quantity: number): number {
    return price * quantity;
}
console.log(calculatePrice("100", 3));
console.log(calculatePrice(100, "3"));
console.log(calculatePrice(100, 3));
  2. See which lines TypeScript underlines in red. Write down the error texts.
  3. Remove the "broken" calls (with strings), leaving only calculatePrice(100, 3). Press Run and verify 300 is printed.
  • В тетради записаны три результата JS (включая странную строку "100100100")
  • В тетради записаны два сообщения об ошибке от TypeScript

  • You concluded: TS prevented the call with wrong arguments

Задание 5. «JS превратился в TS» — миграция файла
Task 5. "JS turned into TS" — migrating a file
Сложно Hard 25 мин
Прочувствовать на практике главное свойство TS: «любой JS — уже TS». Постепенно добавить типы в готовый JS-код. Feel the main TS property in practice: "any JS is already TS". Gradually add types to existing JS code.

Шаги:

Steps:

  1. Откройте typescriptlang.org/play. Удалите весь код и вставьте этот чистый JS (никаких типов!): 
    function greet(name) {
    return "Hello, " + name + "!";
}

const message = greet("Seydi");
console.log(message);
  2. Нажмите Run. Убедитесь, что код работает: в консоли — Hello, Seydi!. Это доказывает: JS-код — это уже валидный TS-код.
  3. Теперь постепенно добавляйте типы:
    • Шаг 1: добавьте тип параметра — function greet(name: string)
    • Шаг 2: добавьте тип возвращаемого значения — : string после скобок
    • Шаг 3: добавьте тип переменной — const message: string = ...
  4. После каждого шага запускайте Run и убеждайтесь, что код работает.
  5. В конце попробуйте сломать: вызовите greet(42). Что скажет TypeScript?
  1. Open typescriptlang.org/play. Delete all code and paste this pure JS (no types!): 
    function greet(name) {
    return "Hello, " + name + "!";
}

const message = greet("Seydi");
console.log(message);
  2. Press Run. Verify the code works: console shows Hello, Seydi!. This proves: JS code is already valid TS code.
  3. Now gradually add types:
    • Step 1: add parameter type — function greet(name: string)
    • Step 2: add return type — : string after the parentheses
    • Step 3: add variable type — const message: string = ...
  4. After each step press Run and verify the code still works.
  5. Finally, try to break it: call greet(42). What does TypeScript say?
  • Исходный JS-код запустился в TS-песочнице без изменений
  • Код прошёл 3 шага «типизации» и продолжает работать
  • В тетрадь записан финальный код целиком + ошибка от greet(42)
  • The original JS code ran in the TS playground without changes
  • The code went through 3 "typing" steps and still works
  • Final code written down in full + the error from greet(42)

Между двумя кружочками над редактором TS Playground переключается отображение «.JS» (скомпилированный код) и «.D.TS» (декларации). Включите «.JS», чтобы увидеть, как ваш TS превращается в JS.

Between the two icons above the editor in TS Playground, you can toggle ".JS" (compiled code) and ".D.TS" (declarations). Turn on ".JS" to see how your TS turns into JS.

Задание 6. Мини-презентация «Зачем нужен TypeScript»
Task 6. Mini-presentation "Why TypeScript matters"
Сложно Hard 30 мин
Подготовить короткое устное выступление (3-5 минут) и объяснить однокурсникам или родителям, что такое TypeScript и зачем он нужен. Prepare a short oral talk (3-5 minutes) and explain to classmates or parents what TypeScript is and why it matters.

План выступления:

Talk outline:

  1. Хук (1 минута): расскажите про баг с "100" * 3 === "100100100". Это «зацепит» слушателя — он сразу поймёт проблему.
  2. Что такое TypeScript (1 минута): «надстройка над JS», добавляет типы, разработана Microsoft с 2010 года.
  3. Как это работает (1 минута): нарисуйте схему app.ts → tsc → app.js → браузер. Подчеркните, что в браузер попадает чистый JS.
  4. Кто использует (1 минута): VS Code, Slack, Discord, Airbnb. Назовите хотя бы 3 продукта, которыми слушатель пользуется лично.
  5. Вывод (30 секунд): почему стоит учить TS в 2026 году.
  1. Hook (1 min): tell the "100" * 3 === "100100100" bug. This grabs the listener — they immediately get the problem.
  2. What is TypeScript (1 min): "a superset of JS", adds types, developed by Microsoft since 2010.
  3. How it works (1 min): draw the app.ts → tsc → app.js → browser diagram. Emphasize that the browser receives plain JS.
  4. Who uses it (1 min): VS Code, Slack, Discord, Airbnb. Name at least 3 products the listener uses personally.
  5. Conclusion (30 sec): why it's worth learning TS in 2026.

Подсказка для хука:

Hook hint:

«Представь, ты заходишь в интернет-магазин и видишь цену "100100100 рублей" вместо "300 рублей". Это реальный баг JavaScript — он молча умножает строку на число. TypeScript — язык, придуманный, чтобы такого не случалось…»

"Imagine: you go to an online store and see a price of '100100100 rubles' instead of '300 rubles'. That's a real JavaScript bug — it silently multiplies a string by a number. TypeScript is the language designed so this never happens…"
