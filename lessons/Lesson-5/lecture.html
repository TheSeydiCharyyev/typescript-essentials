1. Что такое примитивный тип

1. What a primitive type is

В TypeScript (как и в JavaScript) все значения делятся на две группы: примитивы и объекты. Сегодня — про примитивы.

In TypeScript (as in JavaScript) all values fall into two groups: primitives and objects. Today is about primitives.

Примитивное значение — это «простое», «неделимое» значение, у которого нет внутренней структуры в виде полей. В JavaScript их семь: string, number, boolean, bigint, symbol, null, undefined. Сегодня разбираем первые пять. null и undefined — в занятии 7.

A primitive value is a "simple", "atomic" value with no internal field structure. JavaScript has seven of them: string, number, boolean, bigint, symbol, null, undefined. Today we cover the first five. null and undefined are in Lesson 7.

Главное отличие от объектов: примитивы сравниваются по значению, а не по ссылке.

Main difference from objects: primitives compare by value, not by reference.

// Примитивы — сравнение по значению
"hello" === "hello"   // true
42 === 42             // true
true === true         // true

// Объекты — сравнение по ссылке
{ a: 1 } === { a: 1 }     // false! (разные объекты в памяти)
const obj = { a: 1 };
obj === obj               // true (одна и та же ссылка)

Запомните: примитивы — «копия по значению», объекты — «общая ссылка». Поэтому два объекта с одинаковым содержимым — это всё равно разные объекты.

Remember: primitives — "copy by value", objects — "shared reference". Two objects with identical contents are still different objects.

2. string — строки

2. string — strings

string — это последовательность символов, заключённая в кавычки. В JS/TS есть три вида кавычек:

string is a sequence of characters in quotes. JS/TS has three kinds of quotes:

const a = 'одинарные кавычки';
const b = "двойные кавычки";
const c = `обратные кавычки (backticks)`;

Для TypeScript все три типа кавычек дают одинаковый тип — string. Выбор между одинарными и двойными — вопрос стиля проекта (обычно команда договаривается и придерживается одного).

For TypeScript, all three quote styles produce the same type — string. The choice between single and double is a style question (teams usually agree on one).

Когда какие кавычки

Which quotes to use when

  • Двойные " — самый распространённый стиль; настройка по умолчанию в Prettier
  • Одинарные ' — также популярны; короче на 1 символ при наборе
  • Обратные ` — для шаблонных строк (интерполяция, многострочные)
  • Double " — the most common style; Prettier default
  • Single ' — also popular; one character shorter to type
  • Backticks ` — for template strings (interpolation, multi-line)

Эскейпинг (экранирование) и спец-символы

Escaping and special characters

Внутри строки в кавычках того же типа символ нужно «экранировать» обратным слэшем:

Inside a string, a quote of the same type must be "escaped" with a backslash:

const wrong = "Он сказал "Привет""; // ❌ синтаксическая ошибка
const right = "Он сказал \"Привет\"";  // ✅
const easier = 'Он сказал "Привет"';   // ✅ другой тип кавычек — без эскейпа

// Полезные эскейп-последовательности
const newline = "Первая\nВторая";   // \n — перенос строки
const tab = "Имя\tВозраст";          // \t — табуляция
const backslash = "C:\\Users";        // \\ — обратный слэш

3. Template literals — шаблонные строки

3. Template literals — template strings

Самый удобный способ «склеивать» строки с переменными — обратные кавычки и ${...}:

The most convenient way to "weave" variables into strings — backticks and ${...}:

const name = "Сейди";
const age = 20;

// Старый способ: конкатенация через +
const oldWay = "Привет, " + name + "! Тебе " + age + " лет.";

// Современный способ: template literal
const newWay = `Привет, ${name}! Тебе ${age} лет.`;

Внутри ${...} можно писать любое выражение:

Inside ${...} you can put any expression:

const price = 100;
const qty = 3;

const sum = `Итого: ${price * qty} рублей`;            // "Итого: 300 рублей"
const upper = `Имя: ${name.toUpperCase()}`;             // "Имя: СЕЙДИ"
const conditional = `Совершеннолетний: ${age >= 18}`;   // "Совершеннолетний: true"

Многострочные шаблоны

Multi-line templates

Backticks умеют то, чего не умеют обычные кавычки — содержать переносы строк прямо в коде:

Backticks can do what regular quotes can't — contain line breaks right in the code:

const html = `
<div class="card">
    <h1>${name}</h1>
    <p>Возраст: ${age}</p>
</div>
`;

Правило 2026: в новом коде используйте почти всегда template literals вместо конкатенации через +. Это короче, читаемее и меньше шансов ошибиться с пробелами и кавычками.

2026 rule: in new code use template literals almost always instead of + concatenation. Shorter, more readable, fewer chances to mess up spaces and quotes.

4. number — числа

4. number — numbers

number — единый тип для всех числовых значений: целых, дробных, отрицательных, шестнадцатеричных. В отличие от других языков, в TS нет отдельных int и float.

number is a single type for all numeric values: integers, decimals, negatives, hex. Unlike other languages, TS has no separate int and float.

const age: number = 18;
const pi: number = 3.14;
const debt: number = -500;
const hex: number = 0xff;       // 255 в шестнадцатеричной
const binary: number = 0b1010;  // 10 в двоичной
const big: number = 1_000_000;  // подчёркивания для читаемости (= 1000000)

5. NaN, Infinity и другие сюрпризы

5. NaN, Infinity, and other surprises

У типа number есть три «специальных» значения:

The number type has three "special" values:

  • Infinity — положительная бесконечность (например, 1 / 0)
  • -Infinity — отрицательная бесконечность
  • NaN — «Not a Number», результат некорректной арифметической операции
  • Infinity — positive infinity (e.g., 1 / 0)
  • -Infinity — negative infinity
  • NaN — "Not a Number", the result of an invalid arithmetic operation
console.log(1 / 0);                // Infinity
console.log(-1 / 0);               // -Infinity
console.log(0 / 0);                // NaN
console.log(parseInt("abc"));      // NaN
console.log(Number("hello"));      // NaN
console.log(Math.sqrt(-1));        // NaN

Главный сюрприз: NaN !== NaN. Это значит, что нельзя проверить «значение равно NaN?» обычным ===:

const x = NaN;
x === NaN;          // ❌ false (!)
Number.isNaN(x);    // ✅ true — правильная проверка

Main surprise: NaN !== NaN. So you can't check "is this NaN?" with regular ===:

const x = NaN;
x === NaN;          // ❌ false (!)
Number.isNaN(x);    // ✅ true — the correct check

Правило: используйте Number.isNaN(x) для проверки на NaN и Number.isFinite(x) чтобы убедиться, что значение — конечное число (не Infinity, не NaN).

Rule: use Number.isNaN(x) to check for NaN and Number.isFinite(x) to verify a value is a finite number (not Infinity, not NaN).

6. boolean — true/false

6. boolean — true/false

boolean — самый простой тип. Всего два значения: true или false.

boolean is the simplest type. Just two values: true or false.

const isAdmin: boolean = true;
const isVerified: boolean = false;
const isAdult: boolean = age >= 18;     // результат сравнения — тоже boolean

Логические операторы

Logical operators

ОператорНазваниеПример
OperatorNameExample
&&AND (и)true && false → false
||OR (или)true || false → true
!NOT (отрицание)!true → false

Операторы сравнения возвращают boolean

Comparison operators return boolean

5 > 3              // true
5 < 3              // false
5 === 5            // true   (строгое равенство)
5 === "5"          // false  (разные типы)
5 !== 6            // true

В TypeScript всегда используйте === и !== (строгое сравнение), а не == и !=. Строгое сравнение проверяет и значение, и тип; нестрогое — пытается «привести» типы и часто ведёт к багам. Например, 0 == false → true, что почти никогда не то, что вы хотели.

In TypeScript always use === and !== (strict equality), not == and !=. Strict equality checks both value and type; loose equality tries to "coerce" types and often causes bugs. E.g., 0 == false → true, which is almost never what you wanted.

7. Truthy и falsy значения

7. Truthy and falsy values

В JavaScript (и TypeScript) любое значение можно использовать в логическом контексте — например, в if. Тогда значение автоматически приводится к true или false. Запомните 6 falsy значений — всё остальное truthy.

In JavaScript (and TypeScript) any value can be used in a logical context — like inside if. The value is then automatically coerced to true or false. Memorize the 6 falsy values — everything else is truthy.

Шесть falsy значений

The six falsy values

false           // сам false
0               // ноль
-0              // отрицательный ноль
""              // пустая строка
null            // null
undefined       // undefined
NaN             // Not a Number

Всё остальное truthy, включая:

Everything else is truthy, including:

"0"             // строка "0" — truthy!
"false"         // строка "false" — truthy!
[]              // пустой массив — truthy
{}              // пустой объект — truthy
-1              // любое ненулевое число

Это позволяет писать сокращённые проверки:

This enables shorthand checks:

const userName = "";

if (userName) {
    console.log(`Привет, ${userName}!`);
} else {
    console.log("Имя не указано");   // ← попадём сюда: "" — falsy
}

Внимание на ловушки:

  • "0" — это truthy, потому что это непустая строка. Это не то же, что число 0.
  • [] и {} — тоже truthy. Чтобы проверить «массив пустой?» — пишите arr.length === 0.

Watch the traps:

  • "0" is truthy — it's a non-empty string. Different from the number 0.
  • [] and {} are also truthy. To check "is the array empty?" — write arr.length === 0.

8. bigint и symbol — редкие гости

8. bigint and symbol — rare guests

Два примитива, с которыми вы будете встречаться редко — но знать о них надо.

Two primitives you'll rarely meet — but should know about.

bigint — для очень больших целых чисел

bigint — for very large integers

Тип number точно работает с целыми только до 253 - 1 (≈ 9 квадриллионов). Для бóльших — bigint:

Type number precisely handles integers only up to 253 - 1 (≈ 9 quadrillion). For larger — bigint:

const big: bigint = 9007199254740993n;   // суффикс "n" обязателен
const fromInt = BigInt(123);             // или через функцию

// bigint и number не смешиваются!
big + 1n;       // ✅
big + 1;        // ❌ Operator '+' cannot be applied to types 'bigint' and 'number'

Где используется: финансовые расчёты, идентификаторы из БД, криптография.

Where used: financial calculations, database IDs, cryptography.

symbol — уникальные идентификаторы

symbol — unique identifiers

Каждый symbol() — это уникальное значение, не равное никакому другому. Используется как «секретные ключи» для свойств объектов, чтобы избежать коллизий.

Every symbol() is a unique value, equal to no other. Used as "secret keys" for object properties to avoid collisions.

const s1 = Symbol("ключ");
const s2 = Symbol("ключ");
s1 === s2;   // false — несмотря на одинаковое описание

На практике в обычном коде вы будете встречать bigint и symbol 1-2 раза в год. В первый год программирования можно про них «помнить, что есть, но не использовать».

In practice, you'll meet bigint and symbol 1-2 times a year in normal code. In your first year of programming, it's fine to "remember they exist but not use them".

9. Literal types — главная фишка занятия

9. Literal types — the headline of the lesson

А теперь — самое интересное. То, ради чего TypeScript часто и используют.

And now — the most interesting part. What people often use TypeScript for in the first place.

Literal type — это тип, который описывает одно конкретное значение, а не «вообще все строки» или «вообще все числа». Например, тип "red" допускает только строку "red" — и больше ничего.

A literal type is a type that describes one specific value, not "all strings" or "all numbers". For example, the type "red" allows only the string "red" — nothing else.

let status1: string = "ok";        // тип string — любая строка
status1 = "что угодно";            // ✅

let status2: "ok" = "ok";          // тип "ok" — только эта строка!
status2 = "fail";                  // ❌ Type '"fail"' is not assignable to type '"ok"'

На первый взгляд это выглядит странно: «зачем мне переменная, в которую можно положить только одну единственную строку?» Сам по себе — действительно бесполезно. Но в сочетании с union (об этом ниже) литералы становятся мощнейшим инструментом.

At first glance this looks weird: "why would I want a variable that can only hold one single string?" By itself — yes, useless. But combined with a union (next section), literals become an extremely powerful tool.

Литералы есть для всех трёх примитивов:

Literals exist for all three primitives:

let direction: "left" = "left";
let count: 42 = 42;
let flag: true = true;

10. Union из литералов

10. Literal unions

Союзник литералов — оператор | («или»). Можно перечислить через него набор допустимых значений:

Literals' best friend is the | ("or") operator. You can list a set of allowed values:

let direction: "left" | "right" | "up" | "down";

direction = "left";       // ✅
direction = "right";      // ✅
direction = "diagonal";   // ❌ Type '"diagonal"' is not assignable to '"left" | "right" | "up" | "down"'

Это и есть главное применение литералов: защита от опечаток и самодокументирующийся код.

This is the headline use of literals: typo protection and self-documenting code.

Пример: статус задачи

Example: a task status

type TaskStatus = "todo" | "in-progress" | "done" | "archived";

function setStatus(taskId: number, status: TaskStatus) {
    console.log(`Задача ${taskId}: новый статус "${status}"`);
}

setStatus(1, "done");        // ✅
setStatus(2, "in-progress"); // ✅
setStatus(3, "Done");        // ❌ опечатка в регистре — TS поймал!
setStatus(4, "compleated");  // ❌ опечатка в слове — TS поймал!

Зачем это нужно: в JavaScript передать «compleated» вместо «completed» — обычное дело, баг найдётся только в проде, когда статус никогда не сменится. В TypeScript эта опечатка невозможна — литеральный union её отлавливает в редакторе.

Why it matters: in JavaScript passing "compleated" instead of "completed" is a common mistake; you find it in production when statuses never change. In TypeScript that typo is impossible — the literal union catches it in the editor.

VS Code даже подсказывает варианты! Поставьте курсор после setStatus(1, — и редактор предложит выбрать из 4 допустимых значений. Это называется autocomplete, и без TypeScript он невозможен — JS просто не знает, какие значения вы ждёте.

VS Code even autocompletes! Put the cursor after setStatus(1, — and the editor offers a pick from the 4 allowed values. This is called autocomplete, and it's impossible without TypeScript — JS simply doesn't know which values you expect.

11. as const — заморозка литерала

11. as const — freezing a literal

Помните widening из занятия 4? let x = "hello" → string, const x = "hello" → "hello". А что, если значение нужно литеральное, но самой переменной мы хотим let?

Remember widening from Lesson 4? let x = "hello" → string, const x = "hello" → "hello". What if we need a literal type but a let variable?

Есть специальный синтаксис: as const.

There's a special syntax: as const.

let a = "hello";              // тип: string
let b = "hello" as const;     // тип: "hello"  ← заморозили в литерал

const arr1 = [1, 2, 3];           // тип: number[]    ← можно push/pop, менять
const arr2 = [1, 2, 3] as const;  // тип: readonly [1, 2, 3]  ← заморозили!
arr2.push(4);                     // ❌ Property 'push' does not exist on type 'readonly...'

as const делает значение максимально точным и иммутабельным (нельзя изменить). Это критически важно для объектов в стиле «конфиг»:

as const makes a value maximally precise and immutable. Critical for "config-style" objects:

const config = {
    apiUrl: "https://api.example.com",
    timeout: 5000,
    mode: "production"
} as const;

// Без as const:
//   config.apiUrl: string
//   config.timeout: number
//   config.mode: string

// С as const:
//   config.apiUrl: "https://api.example.com"  (литерал!)
//   config.timeout: 5000                       (литерал!)
//   config.mode: "production"                  (литерал!)
//   и весь объект readonly — нельзя изменить

Зачем это полезно? Когда вы пишете функцию, которая ожидает "production" | "development", вы можете передать config.mode — и она пройдёт проверку. Без as const config.mode был бы просто string — и TS не разрешил бы.

Why useful? When you write a function expecting "production" | "development", you can pass config.mode — and it'll typecheck. Without as const, config.mode would just be string — and TS would refuse.

Запомните: as const — это «сделай тип максимально точным и заморозь содержимое». Используется для конфигов, наборов опций, констант. Это один из главных инструментов современного TS 2026.

Remember: as const means "make the type maximally precise and freeze the contents". Used for configs, option sets, constants. One of the headline tools of modern TS 2026.

12. Тизер: template literal types

12. Teaser: template literal types

Подробно мы их разберём в занятии 26, но познакомимся уже сейчас. Помните template literals (раздел 3)? Так вот, у них есть аналог на уровне типов:

We'll cover them in detail in Lesson 26, but let's meet them now. Remember template literals (section 3)? They have a type-level counterpart:

type Greeting = `Hello, ${string}!`;

const a: Greeting = "Hello, World!";   // ✅
const b: Greeting = "Hello, Сейди!";    // ✅
const c: Greeting = "Hi, World!";      // ❌ не начинается с "Hello, "
const d: Greeting = "Hello, World";    // ❌ нет восклицательного знака

Можно даже комбинировать литералы:

You can even combine literals:

type Color = "red" | "green" | "blue";
type Size = "small" | "large";

type ClassName = `${Color}-${Size}`;
//                 ↑
// "red-small" | "red-large" | "green-small" | "green-large" | "blue-small" | "blue-large"

Это можно использовать для типобезопасных CSS-классов, маршрутов API, ключей событий. Подробности — в занятии 26.

Useful for type-safe CSS classes, API routes, event keys. Details in Lesson 26.
