1. Стек TypeScript-разработчика в 2026 году

1. The TypeScript developer's stack in 2026

«Стек» — это набор инструментов, которыми пользуется разработчик. Для современного TypeScript минимальный стек выглядит так:

A "stack" is the set of tools a developer uses. The minimum modern TypeScript stack looks like this:

┌──────────────────────────────────────────────────┐ │ Стек TypeScript-разработчика (2026) │ ├──────────────────────────────────────────────────┤ │ 1. VS Code — редактор, где пишем │ │ 2. Node.js 22+ LTS — среда исполнения JS │ │ 3. npm — менеджер пакетов │ │ 4. typescript (локально)— компилятор tsc │ │ 5. tsx (локально) — раннер .ts напрямую │ │ 6. 4 расширения VS Code — улучшают опыт работы │ └──────────────────────────────────────────────────┘

Все эти инструменты бесплатны и работают на Windows, macOS и Linux. Установим их по очереди.

All these tools are free and work on Windows, macOS, and Linux. We'll install them one by one.

Главное отличие от устаревших гайдов (2018-2022):

  • TypeScript ставим локально в проект (-D), а не глобально (-g) — так каждый проект использует свою версию компилятора
  • Вместо устаревшего ts-node — современный tsx (быстрее, проще, активно поддерживается)
  • Используем Node.js 22+ — он умеет запускать .ts напрямую через флаг --experimental-strip-types

The key difference from older guides (2018-2022):

  • Install TypeScript locally in the project (-D), not globally (-g) — so each project uses its own compiler version
  • Use modern tsx instead of legacy ts-node (faster, simpler, actively maintained)
  • Use Node.js 22+ — it can run .ts directly via the --experimental-strip-types flag

Visual Studio Code (VS Code) is the most popular code editor in the world. Free, made by Microsoft, has built-in TypeScript support out of the box. VS Code itself is 95% TypeScript — so TS development in it is excellent.

3. Что такое Node.js и почему нужна версия 22+

3. What Node.js is and why version 22+ matters

Подождите — мы же учим TypeScript для браузера? Зачем нам Node.js?

Wait — we're learning TypeScript for the browser, right? Why do we need Node.js?

Node.js — это среда исполнения JavaScript вне браузера. Создана в 2009 году Райаном Далем. Использует тот же движок V8, что и Chrome. С её помощью можно: запускать JS-файлы прямо из терминала, ставить пакеты через npm, писать серверы и CLI-утилиты.

Node.js is a JavaScript runtime that works outside the browser. Created in 2009 by Ryan Dahl. It uses the same V8 engine as Chrome. With it you can: run JS files from the terminal, install packages via npm, write servers and CLI tools.

Для нас Node.js нужен по трём причинам:

For us, Node.js is needed for three reasons:

  1. Чтобы установить компилятор TypeScript. Сам tsc — это пакет npm, а npm идёт вместе с Node.js. Нет Node — нет npm — нет tsc.
  2. Чтобы запускать .ts/.js-файлы вне браузера. Через node hello.js (или npx tsx hello.ts) прямо в терминале, без HTML-страницы.
  3. Чтобы устанавливать любые TS-пакеты для будущих проектов. React, Express, Vite, NestJS, Zod — всё ставится через npm.
  1. To install the TypeScript compiler. tsc itself is an npm package, and npm comes with Node.js. No Node — no npm — no tsc.
  2. To run .ts/.js files outside the browser. Via node hello.js (or npx tsx hello.ts) right in the terminal, no HTML page needed.
  3. To install any TS packages for future projects. React, Express, Vite, NestJS, Zod — everything installs through npm.

Почему именно Node.js 22+

Why specifically Node.js 22+

В 2024 году Node.js научился запускать TypeScript-файлы напрямую через флаг --experimental-strip-types. Это работает в Node.js версии 22.6+. В Node.js 23+ этот режим включён по умолчанию.

In 2024 Node.js learned to run TypeScript files directly via the --experimental-strip-types flag. This works in Node.js 22.6+. In Node.js 23+ this mode is on by default.

# Node.js 22+ умеет это:
node --experimental-strip-types hello.ts

# Node.js 23+ умеет это:
node hello.ts

Что это значит: для маленьких скриптов вообще не нужны tsc или tsx — достаточно одного node. Но для реальных проектов мы всё равно ставим TypeScript локально, потому что нужны полная проверка типов, генерация .d.ts и работа с конфигом.

What this means: for small scripts you don't need tsc or tsx at all — just node. But for real projects we still install TypeScript locally because we need full type checking, .d.ts generation, and config support.

5. npm: локально vs глобально

5. npm: local vs global

npm расшифровывается как Node Package Manager. Это программа, которая устанавливается вместе с Node.js и позволяет скачивать и обновлять пакеты — готовые библиотеки чужого кода.

npm stands for Node Package Manager. It's a program that ships together with Node.js and lets you download and update packages — ready-made libraries of other people's code.

Аналогия: npm — это App Store / Google Play для разработчиков. На сегодня в реестре npm — больше 3 миллионов пакетов.

Analogy: npm is the App Store / Google Play for developers. The npm registry today has over 3 million packages.

Почему в 2026 году ставят локально

Why we install locally in 2026

В старых гайдах вы увидите npm install -g typescript. Это всё ещё работает, но устарело. Современный подход — ставить компилятор в каждый проект отдельно:

Old guides will show npm install -g typescript. That still works but is outdated. The modern approach is to install the compiler per project:

Проблема глобальной установкиРешение через локальную
Problem with global installLocal install fixes it
На компьютере одна версия TS — все проекты её делят. Старый проект на TS 4.x ломается, если вы обновили глобальный TS до 5.x.Каждый проект фиксирует свою версию в package.json. Старые проекты работают как работали.
Коллега клонирует ваш проект — у него нет тех же глобальных пакетов. Проект «не собирается».Один раз npm install — и все нужные пакеты автоматически установятся в проект.
На macOS/Linux нужны права sudo для глобальной установки.Локально — никаких sudo, всё в папке проекта.
One TS version on the computer — all projects share it. An old TS 4.x project breaks when you upgrade the global TS to 5.x.Each project pins its own version in package.json. Old projects keep working.
A colleague clones your project — they don't have your global packages. The project "won't build".A single npm install brings in every needed package automatically.
On macOS/Linux global installs need sudo.Local installs need no sudo — everything stays in the project folder.

Запомните флаги npm install:

  • -D (или --save-dev) — пакет нужен только при разработке (компилятор, тесты, форматтер). Это наш случай.
  • без флага — пакет нужен в продакшене (например, express, react).
  • -g — глобально (старайтесь не использовать).

Remember the npm install flags:

  • -D (or --save-dev) — package needed only at development time (compiler, tests, formatter). Our case.
  • no flag — package needed in production (e.g., express, react).
  • -g — globally (try not to use it).

6. Инициализация проекта: npm init

6. Initializing a project: npm init

Прежде чем ставить TypeScript локально, нужно создать проект — папку с файлом package.json, в котором npm будет хранить список зависимостей.

Before installing TypeScript locally, we need to create a project — a folder with a package.json file where npm tracks dependencies.

1

Создайте на рабочем столе папку hello-ts/ и откройте её в VS Code (File → Open Folder).

Create a folder hello-ts/ on your desktop and open it in VS Code (File → Open Folder).

2

Откройте терминал в VS Code (Ctrl+`) и выполните:

Open the terminal in VS Code (Ctrl+`) and run:

npm init -y

Флаг -y означает «согласиться на все настройки по умолчанию». В папке появится файл package.json:

The -y flag means "accept all defaults". A package.json file appears in the folder:

{
  "name": "hello-ts",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  }
}

package.json — это «паспорт» проекта. В нём хранится: имя, версия, скрипты для запуска (npm run ...) и список зависимостей. Этот файл должен быть в каждом TS/JS-проекте.

package.json is the project's "passport". It stores: name, version, scripts (npm run ...), and the dependency list. Every TS/JS project must have this file.

7. Установка TypeScript и tsx локально

7. Installing TypeScript and tsx locally

Главное событие занятия. Две библиотеки одной командой:

The main event of the lesson. Two libraries in one command:

npm install -D typescript tsx

Расшифровка:

Breakdown:

  • npm — вызываем npm
  • install — установить (можно сократить до i)
  • -D — флаг «dev dependency», только для разработки
  • typescript — пакет с компилятором tsc
  • tsx — пакет с раннером для прямого запуска .ts-файлов
  • npm — invoke npm
  • install — install (can be shortened to i)
  • -D — "dev dependency" flag, development-only
  • typescript — package with the tsc compiler
  • tsx — package with the runner that executes .ts files directly

После установки package.json обновится — там появится секция devDependencies:

After install, package.json updates — a devDependencies section appears:

{
  "name": "hello-ts",
  "version": "1.0.0",
  "devDependencies": {
    "typescript": "^5.x.x",
    "tsx": "^4.x.x"
  }
}

А в папке появится node_modules/ — туда скачались все пакеты.

And a node_modules/ folder appears — that's where all packages were downloaded.

Проверка

Verification

npx tsc --version
# Output: Version 5.x.x

npx tsx --version
# Output: tsx v4.x.x

Что такое npx: утилита, которая идёт вместе с npm и умеет запускать любой локально установленный пакет. Без npx терминал не найдёт tsc или tsx, потому что они стоят в node_modules/.bin/, а не в системном PATH.

What npx is: a utility shipped with npm that can run any locally installed package. Without npx the terminal won't find tsc or tsx because they live in node_modules/.bin/, not the system PATH.

Что в .gitignore: папку node_modules/ не коммитят в git — она восстанавливается командой npm install из package.json. Создайте в проекте файл .gitignore со строкой node_modules.

About .gitignore: the node_modules/ folder is never committed to git — it's restored by npm install from package.json. Create a .gitignore file in the project with the line node_modules.

10. Современные альтернативы: Bun и Node 22+ native

10. Modern alternatives: Bun and native Node 22+

В 2024-2025 годах появились два способа запускать TypeScript вообще без установки отдельного компилятора или раннера.

In 2024-2025 two ways appeared to run TypeScript without installing a separate compiler or runner at all.

Вариант 1: Node.js 22+ native TypeScript

Option 1: Node.js 22+ native TypeScript

# Node.js 22.6+
node --experimental-strip-types hello.ts

# Node.js 23+ (включено по умолчанию)
node hello.ts

Node просто «стирает» аннотации типов и запускает то, что осталось — как обычный JS. Подходит для маленьких скриптов.

Node simply "strips" type annotations and runs what's left — like regular JS. Good for small scripts.

Ограничение: native-режим Node не понимает enum, namespaces и параметры конструктора с модификаторами (например, constructor(private name: string)). Поэтому в 2026 году эти возможности TypeScript считаются legacy — мы их будем разбирать в курсе, но писать новый код стоит без них.

Limitation: Node's native mode doesn't understand enum, namespaces, or parameter properties (e.g. constructor(private name: string)). That's why these TS features are considered legacy in 2026 — we'll cover them in the course but write new code without them.

Вариант 2: Bun

Option 2: Bun

Bun — альтернативный JavaScript-рантайм (как Node.js, но другой), который умеет запускать TypeScript «из коробки» без всяких флагов:

Bun is an alternative JavaScript runtime (like Node.js, but different) that runs TypeScript out of the box with no flags:

# Установить Bun (один раз)
# macOS/Linux: curl -fsSL https://bun.sh/install | bash
# Windows:     powershell -c "irm bun.sh/install.ps1 | iex"

# Запустить TS
bun hello.ts

Bun быстрее Node.js на тестах, имеет встроенный пакетный менеджер (заменяет npm), бандлер и тест-раннер. Минус: пока не каждая библиотека работает на Bun одинаково хорошо.

Bun is faster than Node.js in benchmarks, has a built-in package manager (replaces npm), a bundler, and a test runner. Downside: not every library works equally well on Bun yet.

Что выбрать для курса: остаёмся на npm + tsx + Node.js 22+. Это самый стандартный стек, который работает везде и которым пользуется 90% компаний. Bun — попробуйте после курса как «следующий шаг».

What to use for this course: we stick with npm + tsx + Node.js 22+. The most standard stack, works everywhere, used by 90% of companies. Try Bun after the course as a "next step".
