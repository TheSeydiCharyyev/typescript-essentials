Lesson 2: Tools Setup — 6 tasks from install to first run

Задание 1. Установить VS Code и Node.js 22+
Task 1. Install VS Code and Node.js 22+
Легко Easy 15 мин
Поставить два главных инструмента: редактор и среду исполнения. Install the two main tools: the editor and the runtime.

Шаги:

Steps:

  1. Откройте code.visualstudio.com, скачайте и установите VS Code для вашей ОС. На Windows — поставьте галочки «Add to PATH» и «Open with Code».
  2. Откройте nodejs.org, скачайте LTS-версию (зелёная кнопка слева). Запустите установщик, нажимайте Next/Install.
  3. Откройте VS Code. Откройте терминал (Ctrl+`). Запустите: 
    node --version
npm --version
  4. Запишите в тетрадь обе версии.
  1. Open code.visualstudio.com, download and install VS Code for your OS. On Windows — check the boxes "Add to PATH" and "Open with Code".
  2. Open nodejs.org, download the LTS version (green button on the left). Run the installer, click Next/Install.
  3. Open VS Code. Open the terminal (Ctrl+`). Run: 
    node --version
npm --version
  4. Write down both versions in your notebook.
  • VS Code открывается, виден интерфейс
  • node --version показывает v22.x.x или выше
  • npm --version показывает 10.x.x или выше

Задание 2. Создать первый TS-проект
Task 2. Create your first TS project
Легко Easy 10 мин
Создать папку проекта, инициализировать package.json, поставить TypeScript и tsx локально. Create a project folder, initialize package.json, install TypeScript and tsx locally.

Шаги:

Steps:

  1. Создайте на рабочем столе папку my-first-ts/.
  2. Откройте её в VS Code: File → Open Folder.
  3. Откройте терминал и выполните по очереди: 
    npm init -y
npm install -D typescript tsx
  4. Когда установка закончится, посмотрите на левую панель — появились:
    • package.json — «паспорт» проекта
    • package-lock.json — точные версии пакетов
    • node_modules/ — скачанные пакеты
  5. Откройте package.json и проверьте: внутри есть секция devDependencies с двумя пакетами (typescript и tsx).
  6. Запустите проверки: 
    npx tsc --version
npx tsx --version
  7. Запишите в тетрадь обе версии.
  1. Create a folder my-first-ts/ on your desktop.
  2. Open it in VS Code: File → Open Folder.
  3. Open the terminal and run in order: 
    npm init -y
npm install -D typescript tsx
  4. When install finishes, check the left panel — you'll see:
    • package.json — project "passport"
    • package-lock.json — exact package versions
    • node_modules/ — downloaded packages
  5. Open package.json and check: it contains a devDependencies section with two packages (typescript and tsx).
  6. Run the checks: 
    npx tsc --version
npx tsx --version
  7. Write down both versions in your notebook.
  • Папка my-first-ts/ создана и открыта в VS Code
  • В ней есть package.json с секцией devDependencies
  • В ней есть папка node_modules/
  • npx tsc --version и npx tsx --version показывают версии
  • Folder my-first-ts/ created and opened in VS Code
  • It has package.json with a devDependencies section
  • It has a node_modules/ folder
  • npx tsc --version and npx tsx --version show versions

Если случайно набрали tsc --version без npx и получили command not found — это нормально! Мы поставили tsc локально, его надо вызывать через npx.

If you accidentally typed tsc --version without npx and got command not found — that's normal! We installed tsc locally; it must be called via npx.

Задание 3. Hello, TypeScript! — двумя способами
Task 3. Hello, TypeScript! — two ways
Средне Medium 15 мин
Запустить первый .ts-файл двумя разными способами и понять разницу. Run your first .ts file two different ways and understand the difference.

Шаги:

Steps:

  1. В папке my-first-ts/ создайте файл hello.ts со следующим кодом: 
    const greeting: string = "Hello, TypeScript!";
const year: number = 2026;

console.log(greeting);
console.log("Год: " + year);
  2. Способ A — через tsx: 
    npx tsx hello.ts
    Запишите результат, который вывелось в терминал.
  3. Способ Б — через tsc + node: 
    npx tsc hello.ts
node hello.js
    Снова запишите результат.
  4. Откройте файл hello.js, который появился рядом с hello.ts. Сравните оба файла. Запишите в тетрадь: что исчезло при компиляции?
  1. In the my-first-ts/ folder create hello.ts with the code: 
    const greeting: string = "Hello, TypeScript!";
const year: number = 2026;

console.log(greeting);
console.log("Год: " + year);
  2. Way A — via tsx: 
    npx tsx hello.ts
    Write down what's printed to the terminal.
  3. Way B — via tsc + node: 
    npx tsc hello.ts
node hello.js
    Write down the result again.
  4. Open hello.js that appeared next to hello.ts. Compare both files. Write in your notebook: what disappeared during compilation?
  • Оба способа выводят одинаковый результат
  • В тетради записано: что : string и : number исчезают из .js
  • Сделан вывод: tsx быстрее (одна команда), tsc нужен для прод-сборки
  • Both ways print the same result
  • Noted: : string and : number are gone in .js
  • Conclusion: tsx is faster (one command), tsc is for production builds

    • Error Lens: текст ошибки появляется в той же строке, справа
    • Pretty TypeScript Errors: при наведении курсора — красивое окошко с понятным описанием
  4. Сделайте скриншот этой ошибки и запишите в тетрадь текст ошибки.
  5. Верните правильный код (const year: number = 2026;) и сохраните файл — Prettier должен отформатировать его автоматически.

Задание 5. Добавить npm-скрипты и .gitignore
Task 5. Add npm scripts and .gitignore
Средне Medium 15 мин
Сделать проект «удобным»: добавить короткие команды и правильно настроить, что не коммитить в git. Make the project "convenient": add short commands and properly configure what not to commit to git.

Шаги:

Steps:

  1. Откройте package.json. Найдите секцию "scripts" и замените её на: 
    "scripts": {
  "start": "tsx hello.ts",
  "build": "tsc hello.ts",
  "check": "tsc --noEmit hello.ts"
}
  2. Сохраните файл. Теперь в терминале можно писать короткие команды: 
    npm start        # запустит tsx hello.ts
npm run build    # запустит tsc hello.ts
npm run check    # только проверит типы
    Заметьте: для start не нужен run, для остальных — нужен.
  3. Проверьте все три команды.
  4. Создайте файл .gitignore в корне проекта со следующим содержимым: 
    node_modules
*.js
*.js.map
  5. Объясните в тетради (1-2 предложения) зачем мы добавили эти три строки.
  1. Open package.json. Find the "scripts" section and replace with: 
    "scripts": {
  "start": "tsx hello.ts",
  "build": "tsc hello.ts",
  "check": "tsc --noEmit hello.ts"
}
  2. Save the file. Now in the terminal you can use short commands: 
    npm start        # runs tsx hello.ts
npm run build    # runs tsc hello.ts
npm run check    # only checks types
    Note: start doesn't need run, the others do.
  3. Try all three commands.
  4. Create a .gitignore file at the project root with: 
    node_modules
*.js
*.js.map
  5. In your notebook explain (1-2 sentences) why we added these three lines.
  • Все три команды (npm start, npm run build, npm run check) работают
  • Файл .gitignore создан и содержит 3 строки
  • В тетради записано объяснение, зачем игнорируем node_modules и *.js
  • All three commands (npm start, npm run build, npm run check) work
  • .gitignore file created and contains 3 lines
  • Notebook has explanation: why we ignore node_modules and *.js

Подсказка: node_modules огромны и легко восстанавливаются. *.js-файлы — это сборка, они генерируются автоматически из .ts. Хранить «исходник» (TS) и «продукт» (JS) рядом в git — плохая идея.

Hint: node_modules is huge and easily restored. *.js files are build output, auto-generated from .ts. Storing "source" (TS) and "product" (JS) together in git is a bad idea.

Задание 6. Запустить TS вообще без TypeScript
Task 6. Run TS without TypeScript at all
Сложно Hard 20 мин
Попробовать современные альтернативы: запустить .ts-файл через native-режим Node.js и (опционально) через Bun. Try modern alternatives: run a .ts file via Node.js native mode and (optionally) via Bun.

Часть А — Node.js native (обязательно):

Part A — Node.js native (required):

  1. Проверьте версию: node --version.
  2. В папке my-first-ts/ создайте отдельный файл script.ts: 
    const name: string = "Сейди";
const age: number = 20;
console.log(`Привет, ${name}! Тебе ${age} лет.`);
  3. Запустите в зависимости от вашей версии Node:
    • Если Node 23+: node script.ts
    • Если Node 22.6+: node --experimental-strip-types script.ts
    • Если Node ниже 22.6: задание выполнить нельзя, переходите к части Б или обновите Node.
  4. Запишите в тетрадь: команда, результат, использовался ли флаг.
  1. Check the version: node --version.
  2. In the my-first-ts/ folder create a separate file script.ts: 
    const name: string = "Seydi";
const age: number = 20;
console.log(`Hello, ${name}! You are ${age} years old.`);
  3. Run depending on your Node version:
    • If Node 23+: node script.ts
    • If Node 22.6+: node --experimental-strip-types script.ts
    • If Node below 22.6: this part can't be done, go to Part B or upgrade Node.
  4. Write down: command used, result, whether the flag was needed.

Часть Б — Bun (опционально):

Part B — Bun (optional):

  1. Установите Bun (одна команда, см. bun.sh):
    • macOS/Linux: curl -fsSL https://bun.sh/install | bash
    • Windows (PowerShell): powershell -c "irm bun.sh/install.ps1 | iex"
  2. Откройте новый терминал. Проверьте: bun --version.
  3. Запустите тот же файл: bun script.ts.
  4. Запишите результат и сравните скорость со npx tsx script.ts (можно прогнать оба несколько раз).
  1. Install Bun (one command, see bun.sh):
    • macOS/Linux: curl -fsSL https://bun.sh/install | bash
    • Windows (PowerShell): powershell -c "irm bun.sh/install.ps1 | iex"
  2. Open a new terminal. Check: bun --version.
  3. Run the same file: bun script.ts.
  4. Write down the result and compare speed with npx tsx script.ts (you can run both several times).
  • Часть А: запустили .ts-файл через node без установки TypeScript
  • В тетради записаны все 3 способа: npx tsx, node, (опц.) bun
  • Сделан вывод: современные раннеры делают «лестницу инструментов» короче
  • Part A: ran the .ts file via node without installing TypeScript
  • Notebook records all 3 ways: npx tsx, node, (opt.) bun
  • Conclusion: modern runners shorten the tool ladder

Не получилось обновить Node до 22.6+? Используйте nvm (Node Version Manager) — это позволит держать несколько версий Node параллельно и переключаться между ними. Это пригодится в реальной работе.

Couldn't upgrade Node to 22.6+? Use nvm (Node Version Manager) — keep multiple Node versions in parallel and switch between them. Useful in real-world work.
