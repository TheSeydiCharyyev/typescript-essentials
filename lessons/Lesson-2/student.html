1. Стек TypeScript-разработчика 2026

1. The 2026 TypeScript developer's stack

Стек — это набор инструментов, которыми пользуется разработчик. Современный TS-стек: VS Code + Node.js 22+ + npm + локально установленные typescript и tsx.

Stack is the set of tools a developer uses. The modern TS stack: VS Code + Node.js 22+ + npm + locally installed typescript and tsx.

Главное правило 2026: ставим TypeScript локально в каждый проект (-D), а не глобально (-g). Это даёт каждому проекту свою версию компилятора.

Main 2026 rule: install TypeScript locally in each project (-D), not globally (-g). Each project gets its own compiler version.

3. Команды, которые надо запомнить

3. Commands to memorize

# Проверка установки
node --version          # должно быть v22.x или новее
npm --version           # должно быть 10.x или новее

# Создание нового проекта
mkdir my-project
cd my-project
npm init -y             # создаёт package.json

# Установка TS-стека локально
npm install -D typescript tsx

# Проверка
npx tsc --version
npx tsx --version

# Запуск .ts-файла
npx tsx app.ts          # сразу запустить (для экспериментов)
npx tsc app.ts          # скомпилировать в app.js
node app.js             # запустить скомпилированный .js

# Только проверить типы, без генерации .js
npx tsc --noEmit

Запомни: -D = «dev dependency» (только разработка), без флага = «production dependency» (нужно и в проде), -g = глобально (старайся не использовать).

Remember: -D = "dev dependency" (development only), no flag = "production dependency" (needed in prod too), -g = global (avoid).

5. tsx vs ts-node vs tsc

5. tsx vs ts-node vs tsc

  • tsc — официальный компилятор. Превращает .ts → .js. Используется в любом production-проекте.
  • tsx — современный раннер (2022+). Делает «tsc + node» одной командой. Быстро. Это то, чем мы пользуемся ежедневно.
  • ts-node — старый раннер. В 2026 году считается устаревшим. Заменён на tsx.
  • tsc — the official compiler. Turns .ts → .js. Used in any production project.
  • tsx — modern runner (2022+). Does "tsc + node" in one command. Fast. What we use daily.
  • ts-node — the old runner. Considered legacy in 2026. Replaced by tsx.

6. Файлы и папки проекта

6. Project files and folders

my-project/ ├── node_modules/ ← скачанные пакеты (в .gitignore, не коммитим) ├── package.json ← «паспорт» проекта: имя, зависимости, скрипты ├── package-lock.json ← точные версии всех пакетов (коммитим) ├── .gitignore ← список папок/файлов, которые игнорирует git └── app.ts ← наш TypeScript-код

В .gitignore обязательно: node_modules — эта папка может весить сотни мегабайт, восстанавливается из package.json командой npm install.

Must be in .gitignore: node_modules — this folder can be hundreds of megabytes and is restored from package.json via npm install.

8. Альтернативные раннеры

8. Alternative runners

  • Node.js 22.6+ с флагом --experimental-strip-types — запускает .ts напрямую
  • Node.js 23+ — то же самое, но без флага (включено по умолчанию)
  • Bun — альтернативный рантайм, понимает TS «из коробки»
  • Node.js 22.6+ with the --experimental-strip-types flag — runs .ts directly
  • Node.js 23+ — same, but no flag (on by default)
  • Bun — alternative runtime, understands TS out of the box

Ограничение native-режима Node: не работают enum, namespaces, параметры конструктора. Поэтому эти возможности TS уходят в legacy.

Limitation of Node's native mode: enum, namespaces, parameter properties don't work. That's why these TS features are becoming legacy.
