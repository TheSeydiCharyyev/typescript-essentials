1. Что такое переменная

1. What a variable is

Переменная — это именованный «контейнер» для хранения значения. В TS/JS объявляется тремя ключевыми словами: let, const, var.

A variable is a named "container" for storing a value. In TS/JS declared with three keywords: let, const, var.

Запоминалка: «const сначала, let если надо менять, var никогда».

Mnemonic: "const first, let if it must change, var never".

Важно про const: запрещает переназначение, но не изменение полей объекта/массива.

Important about const: forbids reassignment, not mutation of object/array fields.

const user = { name: "Anna" };
user = { name: "Boris" };   // ❌ нельзя
user.name = "Boris";        // ✅ можно

3. Аннотация типа

3. Type annotation

Синтаксис: let <имя>: <тип> = <значение>;

Syntax: let <name>: <type> = <value>;

let age: number = 18;
let userName: string = "Anna";
let isAdmin: boolean = false;

Три базовых типа (подробнее в занятии 5):

Three basic types (more in Lesson 5):

  • number — числа (целые, дробные)
  • string — строки в кавычках
  • boolean — true или false
  • number — numbers (integer, decimal)
  • string — strings in quotes
  • boolean — true or false

4. Type inference — TS «угадывает» тип

4. Type inference — TS "guesses" the type

Type inference — способность TypeScript автоматически определять тип переменной по присвоенному значению. Не надо писать : number, если значение уже число.

Type inference — TypeScript's ability to automatically figure out a variable's type from its assigned value. No need to write : number if the value is already a number.

let age = 18;              // TS выводит: number
const userName = "Anna";   // TS выводит: "Anna" (литерал)
const isAdmin = false;     // TS выводит: false (литерал)

Где inference работает:

Where inference works:

  • Объявление с инициализацией: let x = 5
  • Возврат из функции (тип возврата выводится сам)
  • Свойства объектов
  • Большинство выражений
  • Declaration with initializer: let x = 5
  • Return from a function (return type inferred automatically)
  • Object properties
  • Most expressions

Где inference НЕ работает (нужна аннотация):

Where inference does NOT work (annotation required):

  • Объявление без значения (let x;)
  • Параметры функций (function f(x))
  • Данные с границы системы (API-ответ, чтение файла)
  • Declaration with no value (let x;)
  • Function parameters (function f(x))
  • Data from system boundaries (API response, file read)

5. Widening: let vs const с литералами

5. Widening: let vs const with literals

ОбъявлениеВыведенный тип
DeclarationInferred type
let x = 5number

let s = "hi"string
const s = "hi""hi" (литерал)
let x = 5number
const x = 55 (literal)
let s = "hi"string
const s = "hi""hi" (literal)

Почему так: let можно переназначить → TS «расширяет» тип. const переназначить нельзя → точный (литеральный) тип.

Why: let can be reassigned → TS "widens" the type. const can't → exact (literal) type.

6. Главное правило 2026

6. The 2026 headline rule

«Аннотируй границы — параметры функций и явный возврат. Доверяй inference внутри.»

"Annotate boundaries — function parameters and explicit returns. Trust inference inside."

// ✅ Идиоматически
function calculatePrice(price: number, quantity: number): number {
    const total = price * quantity;     // inference: number
    const taxRate = 0.13;               // inference: number
    return total * (1 + taxRate);
}

// ❌ Слишком много аннотаций — лишний шум
function calculatePrice(price: number, quantity: number): number {
    const total: number = price * quantity;
    const taxRate: number = 0.13;
    return total * (1 + taxRate);
}

8. Чтение ошибки TS

8. Reading a TS error

Type 'string' is not assignable to type 'number'.
     ↑                             ↑
   что положили                  что ожидалось

Перевод: «вы передаёте строку, а ждали число».

Translation: "you're passing a string where a number is expected".

9. TDZ — Temporal Dead Zone

9. TDZ — Temporal Dead Zone

«Мёртвая зона» с начала скоупа до строки объявления let/const. Использовать переменную до объявления — ошибка ReferenceError. Это защита.

"Dead zone" from the start of scope to the let/const declaration. Using the variable before declaration → ReferenceError. This is protection.

console.log(y);   // ❌ Cannot access 'y' before initialization
let y = 5;
